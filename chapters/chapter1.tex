    \section{Contexto e Motivação}

    O uso prolongado do computador em contextos de trabalho e estudo cria oportunidades únicas para a monitorização contínua do estado do utilizador através dos sensores integrados ou conectáveis a este dispositivo~\cite{keyboard_correction_study,keyboard_speed_study,facial_hrv_study}. Estes sensores permitem recolher não só dados biométricos, como a frequência cardíaca ou expressões faciais~\cite{facial_hrv_study}, mas também dados comportamentais, como padrões de digitação no teclado~\cite{keyboard_speed_study,keyboard_correction_study}.

    Como se verá no Capítulo~\ref{chap:estadodaarte}, as plataformas \textit{open-source} existentes para recolha de dados de sensores (como o RADAR-base~\cite{radarbase} ou a AWARE Framework~\cite{aware}, por exemplo) focam-se maioritariamente em dispositivos móveis e não suportam sensores de computador, não existindo atualmente nenhuma solução adequada à recolha contínua e remota de dados em estudos longitudinais neste contexto. 
    Este trabalho propõe, por isso, uma infraestrutura em \textit{streaming} que permite a monitorização contínua e assíncrona de dados de sensores de forma modular, extensível e agnóstica ao tipo de sensor.

    \section{Objetivos}\label{sec:objectives}

    Os objetivos concretos do trabalho são:
    \begin{itemize}
        \item Desenvolver um servidor de ingestão de dados baseado em \ac{MQTT} e Kafka, capaz de receber dados de múltiplos sensores e de múltiplos utilizadores em simultâneo.
        \item Definir um protocolo de ingestão agnóstico baseado num contrato mínimo (\ac{UUID}, \textit{timestamp}, nome do sensor e valores) que permita a adição de novos tipos de sensores sem alterar o servidor.
        \item Desenvolver uma aplicação de \textit{desktop} baseada num sistema de \textit{plugins} que facilite a integração de novos sensores.
        \item Desenvolver umna aplicação para WearOS que permita a recolha de \ac{BPM} de um \textit{smartwatch}.
        \item Validar o sistema através de um fluxo \textit{end-to-end} com dados reais e de uma análise analítica de escalabilidade.
        \item Validar o sistema através de um fluxo \textit{end-to-end} com dados reais, de uma análise analítica de escalabilidade e de um \textit{dashboard} Grafana para monitorização
    \end{itemize}

    
    \section{Metodologia}

    O desenvolvimento da arquitetura seguiu uma abordagem incremental por componente, na qual cada elemento da arquitetura foi desenvolvido e validado de forma independente antes de ser integrado, sendo depois novamente testado para garantir a sua correta integração no sistema.

    De modo a guiar o desenvolvimento, foi também estabelecida a seguinte ordem de implementação:
    \begin{enumerate}
        \item servidor (excluindo API REST)
        \item estrutura central da app \textit{desktop} (\textit{broker} local e sistema de \textit{plugins})
        \item \textit{plugins} de câmara e teclado
        \item app para WearOS (e \textit{plugin} de \ac{BPM})
        \item API REST
        \item Finalização da app \textit{desktop} (paineis de controlo e de visualização)
        \item \textit{Dashboard} Grafana
    \end{enumerate}

    Finalmente, foi realizada uma validação em tempo real utilizando o \textit{dashboard} de Grafana de modo a garantir o correto funcionamento do sistema, bem como uma validação analítica do tamanho e frequência das mensagens, de modo a garantir que o sistema é capaz de escalar de forma eficiente.
